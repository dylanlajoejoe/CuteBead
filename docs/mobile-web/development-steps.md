# 手机网页版开发步骤文档

## 阶段 1：确认移动端目标

- 明确手机端不是桌面版缩小，而是单列流程式页面。
- 明确手机端第一优先级是预览区可用，其次才是参数区完整展开。
- 明确手机端和桌面端共用算法，但不共用完全相同的布局结构。

## 阶段 2：梳理现有页面结构

- 查看现有 `App.tsx` 的模块划分。
- 查看现有 `styles.css` 的双栏布局规则。
- 确认哪些 DOM 结构可以继续复用，哪些需要重排。

## 阶段 3：先调整页面顺序

- 在手机端把预览区提前。
- 让用户上传图片后更快看到图纸区域。
- 保留上传、设置、统计四个主模块，但重新安排视觉优先级。

## 阶段 4：实现手机端布局分支

- 保留桌面端双栏布局。
- 为手机端增加单列布局规则。
- 调整卡片宽度、间距、标题字号、按钮高度和滚动区域。

## 阶段 5：实现手机端预览优先

- 将预览区固定为正方形。
- 让预览区在手机上占据更高优先级。
- 让预览在小屏下可以滚动查看，不撑坏整体页面。

## 阶段 6：重排参数区和统计区

- 让底板选择、色卡选择和合并强度在小屏下自然换行。
- 让统计区从密集列表改为更适合手机阅读的节奏。
- 保证导出按钮始终清晰可见。

## 阶段 7：做手机端交互细化

- 调整按钮点击范围。
- 调整上传区高度。
- 调整错误提示、空状态和提示文案。
- 评估是否需要在小格时自动隐藏色号。

## 阶段 8：验证桌面与手机共存

- 检查桌面端布局是否仍然成立。
- 检查手机端单列流程是否顺畅。
- 检查 `52 / 78 / 104 / 208` 四种底板在预览区的表现。

## 阶段 9：构建验证

- 运行 Web 构建。
- 检查是否有样式冲突或组件逻辑问题。
- 整理第一版手机网页版可交付结果。
