# 小程序开发步骤文档

## 阶段 1：确定工程结构

- 在项目根目录下建立 `miniprogram/` 工程目录。
- 在项目根目录下预留 `shared/` 目录，后续放共享算法。
- 明确 Web 和小程序各自独立开发，共享仅限纯逻辑和数据。

## 阶段 2：抽离共享能力

- 先抽离 `types`。
- 再抽离色卡 JSON 和读取逻辑。
- 再抽离颜色距离计算、代表色提取、频率合并、图纸生成逻辑。
- 保证共享模块不依赖 `window`、`document`、DOM Canvas。

## 阶段 3：搭建小程序骨架

- 初始化页面路由。
- 建立首页和基础布局。
- 配置全局样式变量和通用组件样式。
- 先做静态界面，不接真实生成逻辑。

## 阶段 4：完成上传与参数区

- 接入图片选择。
- 完成原图预览。
- 完成底板尺寸选择，默认 `104 x 104`。
- 完成色卡选择、合并强度、图案大小设置。
- 完成生成按钮禁用、加载和错误提示。

## 阶段 5：接入图片处理链路

- 打通小程序图片路径到像素读取链路。
- 将图片数据送入共享算法生成图纸数据。
- 确认四种底板尺寸都能返回结果。
- 优先验证 `52 / 78 / 104` 三档结果稳定。

## 阶段 6：完成图纸预览

- 绘制正方形底板。
- 绘制颜色块、色号和辅助网格。
- 让预览区在手机端尽量保持为主视觉区域。
- 增加缩放、拖动或分区查看中的至少一种能力。

## 阶段 7：完成统计与保存

- 展示总豆数、颜色数、各色号数量。
- 生成可导出的图纸图片。
- 接入保存到相册能力。
- 补齐保存失败和权限异常提示。

## 阶段 8：做性能和体验优化

- 观察 `208 x 208` 的生成耗时和内存占用。
- 优化长时间生成时的加载反馈。
- 优化手机端滚动、按钮触达和信息折叠方式。
- 评估是否加入分板查看，降低手机端阅读压力。

## 阶段 9：真机测试

- 用微信开发者工具完成基础联调。
- 用安卓和 iPhone 真机分别验证。
- 用人像、动漫、浅色、深色、透明背景图片分别测试。
- 记录性能瓶颈和错误场景，回到前面阶段修正。

## 阶段 10：第一版收尾

- 清理无用代码和调试逻辑。
- 检查文案、空状态、权限提示一致性。
- 整理最小可发布功能范围。
- 准备提交体验版或审核版。
